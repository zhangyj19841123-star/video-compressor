# 常见问题

### 会不会损伤画质？

默认 CRF 16 属于视觉近无损：实测全片 SSIM `0.999323`、PSNR `57.94 dB`，肉眼基本看不出差别。它是有损重编码（不是无损），但差异远小于一次平台上传压缩。想要更小就切 CRF 20/22，想绝对保留原始比特流则不适合用本工具。

### 为什么有的视频压完反而更大？

如果源文件本身已经是高压缩率的 HEVC / AV1，或者画面噪点很多、运动极复杂，重新编码可能不划算。工具不会自动跳过，遇到这种情况把结果和原文件对比一下，保留更小的那份即可。

### Windows 7 上打不开压缩后的视频

Win7/8 自带播放器不支持 HEVC。请用 [VLC](https://www.videolan.org/) 或 PotPlayer 播放，或在界面「编码」里改选 **H.264 · 老设备兼容**（体积会大一些，但任何设备都能播）。

### 拖进去没反应？

- 确认是**把文件拖到窗口里面**再松手，而不是拖到 Finder / 桌面。
- Windows：必须**整个文件夹解压出来**再运行，只把 `.bat` 单独拖出来会找不到 `bin/ffmpeg.exe`。
- Windows：如果 GUI 被公司安全策略拦截，把视频拖到 `Drag videos onto me.bat` 上，用纯命令行方式压。
- macOS：首次打开若被系统拦截，右键 App → 打开 → 再点「打开」。

### 支持哪些输入格式？

mp4 / mov / mkv / avi / m4v / webm 等 ffmpeg 能解的常见容器都可以，输出统一为 `.mp4`。不支持受 DRM 保护的视频。

### 原文件会被改掉吗？

不会。输出是**新文件**（`原名_压缩版.mp4`），同名自动加序号，原文件始终只读。

### 输出在哪里？

macOS 默认在源文件同目录，Windows 默认在「视频 > 视频压缩输出」，界面里都可以改。完成后可点「在 Finder / 资源管理器中显示」。

### 音画不同步怎么办？

输出已强制恒定帧率（`-fps_mode cfr`）并固定 MP4 时间基（`-video_track_timescale 30000`），正常不会出现。若源文件本身是变速帧率且音轨对不齐，可尝试关闭「保留音轨」重新压一次。

### 压缩要多久？

取决于 CPU 和视频长度。参考：M 系列 Mac、`medium` 预设、171 秒的 2940×1912 录屏约 3 分 50 秒。批量任务串行执行，避免多任务抢占导致掉帧或卡顿。

### 会不会把我的视频上传到服务器？

不会。程序只调用本机内嵌的 ffmpeg，没有任何网络请求、账号体系或遥测。可断网使用。

### Intel Mac 能用吗？

macOS 成品包内嵌 arm64 ffmpeg，仅 Apple Silicon 可用。Intel Mac 请按 [macos/README.md](../macos/README.md) 换成 x86_64 版 ffmpeg 后重跑 `build.sh`。

### 为什么不做成单个 exe / 带安装包的版本？

为了在原生 Win7 x64 上零依赖运行，Windows 版使用系统自带的 PowerShell 2.0 + WinForms，并保留纯 `.bat` 保底路线，不引入 UCRT / VC++ 运行库或安装程序。代价是必须绿色解压整个文件夹。

### 我能改代码再发布吗？

可以，GPL-3.0 允许修改和再分发，但衍生作品须同样以 GPL-3.0 开源并提供源码。详见 [NOTICE.md](../NOTICE.md)。
